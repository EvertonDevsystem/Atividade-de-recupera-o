Eixo 1 · Manipulação da árvore DOM

DOM — Document Object Model: a árvore que o JavaScript manipula

Quando o navegador recebe o HTML, ele não guarda só texto: ele converte o documento em um objeto vivo, a árvore DOM, acessível pelo objeto global document. O JavaScript usa essa árvore para ler o conteúdo, trocar textos e cores, inserir e remover elementos e responder a ações do usuário — sem recarregar a página.

Estrutura em árvore

Cada parte do HTML vira um nó: nós de elemento (tags), nós de texto (conteúdo visível) e nós de atributo (propriedades da tag). A raiz é document.

  • document (raiz)
    • <html>
      • <head>
        • <title> → "Página"
      • <body>
        • <h1> → "Título"
        • <ul id="lista"> atributo id
          • <li> → "Item 1"
          • <li> → "Item 2"
elemento nó de tag texto conteúdo atributo propriedade

Como o JavaScript usa a árvore

  • Selecionar: localizar nós com getElementById, querySelector e querySelectorAll.
  • Navegar: subir e descer pela árvore com parentNode, children, nextElementSibling.
  • Alterar: trocar textContent, atributos com setAttribute e classes com classList.
  • Criar e inserir: createElement + appendChild / append.
  • Remover: remove() no nó selecionado.
  • Reagir a eventos: addEventListener("click", ...) em cliques, digitadores e envios de formulário.

Cuidado: innerHTML injeta HTML bruto e pode permitir XSS quando o texto vem do usuário; prefira textContent para conteúdo simples.

    Eixo 2 · Assincronia de processos web

    Requisição, processamento e resposta: a web que não trava a tela

    O JavaScript do navegador rota em uma única linha de execução: se o código esperasse uma resposta da rede de forma direta, a página congelaria. Por isso as operações de rede são assíncronas: a requisição é enviada, a página continua respondendo e, quando a resposta chega, uma função de tratamento é executada.

    Ciclo de uma requisição web

    1

    Requisição · Cliente

    Um evento (clique, carregamento, envio de formulário) dispara fetch(). O navegador monta a mensagem com método HTTP, URL, cabeçalhos e corpo, e envia pela rede — sem esperar.

    2

    Processamento · Servidor

    O servidor recebe a requisição, verifica autenticação e permissões, executa a regra de negócio, consulta o banco de dados e monta a resposta a devolver.

    3

    Resposta · Cliente

    Chegam o código de status, os cabeçalhos e o corpo (em geral JSON). A promessa é resolvida, os dados são convertidos e o JavaScript atualiza o DOM com o resultado.

    Callbacks

    Função passada como argumento para rodar depois, quando o resultado estiver pronto. Em cadeias de dependência vira aninhamento profundo, o chamado “callback hell”.

    Promises

    Objeto que representa um resultado futuro, em um de três estados: pendente, realizada ou rejeitada. Encadeada com .then() e tratada com .catch().

    async / await

    Sintaxe moderna que faz o código assíncrono parecer síncrono dentro de uma função async; await pausa apenas aquela função, e try/catch trata falhas de rede.

    consumo-assincrono.js
    async function carregarUsuario(id) {
  const url = `https://jsonplaceholder.typicode.com/users/${id}`;
  try {
    // Requisição enviada (estado pendente); a página não trava
    const resposta = await fetch(url);
    if (!resposta.ok) throw new Error("Status " + resposta.status);

    // Corpo da resposta (JSON) convertido em objeto JavaScript
    const usuario = await resposta.json();
    return usuario;
  } catch (erro) {
    console.error("Falha na requisição:", erro.message);
  }
}

    Eixo 2 · Conceitos de API

    API — Application Programming Interface: o contrato de comunicação

    Uma API é o conjunto de regras, endereços e formatos que permite que dois sistemas conversem sem que um precise conhecer o funcionamento interno do outro. Na web, as APIs REST usam o protocolo HTTP: o front-end pede recursos com métodos específicos e o servidor devolve dados, geralmente em JSON.

    Analogia: o garçom do restaurante

    O cliente (front-end) não entra na cozinha (servidor/banco de dados). O garçom (API) leva o pedido — a requisição com o verbo e os dados — até a cozinha e traz de volta o prato pronto — a resposta com status e conteúdo. Basta seguir o cardápio: quais pedidos existem (endpoints) e como fazê-los (métodos e formato).

    • Endpoint: endereço de um recurso, ex.: /users, /users/3.
    • Método HTTP: o que se quer fazer com o recurso (consultar, criar, atualizar, excluir).
    • Corpo e cabeçalhos: dados enviados e metadados como tipo de conteúdo e token de autenticação.
    • Status code: resumo numérico do resultado da operação.

    Anatomia de uma troca HTTP

    Requisição

    • Linha: método + caminho, ex.: GET /users/3
    • Cabeçalhos: Content-Type: application/json, Authorization: Bearer <token>
    • Corpo: dados em JSON (presente em POST, PUT, PATCH)

    Resposta

    • Status: código + mensagem, ex.: 200 OK
    • Cabeçalhos: tipo do conteúdo, tamanho, cache
    • Corpo: JSON com os dados solicitados ou mensagem de erro
    MétodoFinalidadeStatus comum
    GETConsultar recursos (lista ou detalhe)200 OK
    POSTCriar um novo recurso201 Created
    PUTSubstituir o recurso completo200 / 204
    PATCHAtualizar apenas parte do recurso200 OK
    DELETERemover o recurso204 No Content

    Eixo 2 · Conversões do formato JSON

    JSON — JavaScript Object Notation: o texto que vira objeto e volta a texto

    JSON é um formato textual leve de troca de dados, inspirado na sintaxe de objetos JavaScript, mas usado por qualquer linguagem. Na comunicação web os dados trafegam como texto: a API devolve uma string JSON, o código usa JSON.parse() para virar um objeto JavaScript e, ao enviar dados, usa JSON.stringify() para voltar a texto.

    objeto JavaScript (dentro do código)
    const usuario = {
  nome: "Ana",             // chave sem aspas
  idade: 28,
  ativo: true,
  saudar() { return "Oi!" }, // função não existe no JSON
  apelido: undefined          // é descartado na conversão
};
    dados.json (texto puro para a rede)
    {
  "nome": "Ana",
  "idade": 28,
  "ativo": true,
  "tags": ["dev", "web"],
  "endereco": { "cidade": "São Paulo" },
  "salario": null
}

    Regras da sintaxe JSON

    • Chaves e strings usam aspas duplas; números, true, false e null ficam sem aspas.
    • Objetos usam { } e listas usam [ ], com valores podendo se aninhar.
    • Proibido: comentários, funções, variáveis, undefined, aspas simples e vírgula depois do último item.
    • Não é um objeto “vivo”: antes de ler dado.nome, é preciso converter com JSON.parse().

    As duas conversões essenciais

    • JSON.parse(texto): string recebida da API → objeto/array JavaScript utilizável.
    • JSON.stringify(obj, null, 2): objeto → texto JSON; o terceiro argumento ajusta a identação para leitura.
    • JSON malformado faz parse() lançar SyntaxError; por isso envolva em try/catch.
    conversoes-json.js
    const texto = '{"nome":"Ana","idade":28,"ativo":true}';

try {
  // Texto → objeto JavaScript
  const objeto = JSON.parse(texto);
  console.log(objeto.nome);            // "Ana"
} catch (erro) {
  console.error("JSON inválido:", erro.message);
}

// Objeto → texto JSON formatado (para enviar no body de uma requisição)
const textoJson = JSON.stringify(objeto, null, 2);

    Eixo 3 · Armazenamento interno (Web Storage)

    Web Storage: dados que ficam no próprio navegador do usuário

    A Web Storage API guarda pares chave → valor dentro do navegador, sem enviar nada ao servidor a cada leitura. As duas formas principais são localStorage (persistente) e sessionStorage (por aba/sessão); é o mecanismo por trás de preferências de tema, nome do usuário e estados temporários de formulário.

    RecursoPersistênciaEscopoCapacidadeVai ao servidor?Uso típico
    localStoragePermanece após fechar o navegadorMesma origem; compartilhado entre abas~5–10 MBNãoTema, preferências, rascunho
    sessionStorageSome ao fechar a abaApenas a aba aberta no momento~5 MBNãoDados temporários de etapa
    CookiesExpira conforme data definidaMesmo domínio~4 KBSim, em toda requisição HTTPSessão e autenticação
    IndexedDBPersistenteNo navegadorGrande volume estruturadoNãoDados offline e consultas locais (referência)
    web-storage.js
    // Escrita: tudo é armazenado como string
localStorage.setItem("nomeUsuario", "Ana");
localStorage.setItem("tema", "escuro");

// Leitura
const nome = localStorage.getItem("nomeUsuario");

// Remoção
localStorage.removeItem("tema");  // uma chave
localStorage.clear();                 // tudo da origem

// sessionStorage: vale só enquanto a aba estiver aberta
sessionStorage.setItem("etapaAtual", "2");

    Pontos importantes

    • Chaves e valores são sempre strings: para objetos, use JSON.stringify() na escrita e JSON.parse() na leitura.
    • Isonomia de origem: só é visível na mesma combinação de protocolo, domínio e porta.
    • Os dados ficam acessíveis no painel do navegador (DevTools → Application); não guarde senhas ou segredos sensíveis ali.
    • A API é síncrona e simples; para grandes volumes ou busca estruturada, o caminho é IndexedDB.

    Eixo 3 · Modularização em uma aplicação JavaScript

    Módulos: o código dividido em arquivos com export e import

    Modularizar é dividir a aplicação em pequenos arquivos (módulos), cada um com uma responsabilidade clara, que exportam o que pode ser reutilizado e importam de outros arquivos quando precisam. Nos navegadores, a ferramenta nativa são os ES Modules, ativados com <script type="module">.

    Antes × depois

    Sem modularização: um único script.js com tudo — funções misturadas, variáveis no escopo global, risco de nomes conflitantes e difícil manutenção.

    Com módulos: utils.js (ajudadores), api.js (requisições), ui.js (DOM) e app.js (ponto de entrada); cada arquivo importa apenas o que usa.

    • Escopo próprio por arquivo: variáveis não vazam para o global.
    • export define o que o módulo oferece; import define o que o consumo recebe.
    • Tipos de export: nomeado (vários) e default (um por arquivo).
    • Em projeto real, módulos precisam ser servidos por HTTP (Live Server, por exemplo); file:// bloqueia imports por política de segurança.

    Fluxo de arquivos

    index.html → <script type="module" src="app.js">
    app.js → import { saudacao, somar } from "./utils.js"
    utils.js → export const saudacao … / export default function somar …
    Reuso
    uma função em vários pontos
    Manutenção
    cada erro tem um arquivo dono
    Organização
    divisão por responsabilidade
    utils.js — módulo que exporta
    // Export nomeado: pode haver vários
export const saudacao = "Olá, módulo!";

export function formatarData(data) {
  return new Date(data).toLocaleDateString("pt-BR");
}

// Export default: apenas um por arquivo
export default function somar(a, b) {
  return a + b;
}
    app.js — ponto de entrada que importa
    import somar, { saudacao, formatarData } from "./utils.js";

console.log(saudacao);
console.log("2 + 3 =", somar(2, 3));
console.log("Hoje:", formatarData(new Date()));

// Outros módulos da app: api.js (fetch), ui.js (DOM), storage.js
